# تقرير الجولة 66 — أقسام القناة المنفصلة + العزل التلقائي للسنوات + معالجة جدول Supabase بلا لوحة تحكم

## طلبات المالك في هذه الجولة

1. **«القناة فيها عدة أقسام (مواضيع) — أريد إضافتها منفصلة، لكنه يقول القناة مربوطة مسبقاً»**
   (409 عند لصق رابط قسم مثل `t.me/c/xxx/12` في «ربط قناة»).
2. **«فلترة السنوات تلقائية داخلية — لا يختارها الطالب»**:
   منشورات ومواد السنة الأولى تظهر لطلبة السنة الأولى فقط، والثانية للثانية، تلقائياً.
3. **«لا أحتاج لقطات شاشة؛ اعتنِ بجدول Supabas»** — أُنجزت بلا أي خطوة يدوية في لوحة التحكم (التفاصيل أدناه).

---

## ١) أقسام القناة المنفصلة (إصلاح الـ409 نهائياً)

**قبل r66:** لصق رابط قسم تحت قناة مربوطة → 409 «هذه القناة مربوطة مسبقاً»، لأن مفتاح
التكرار كان معرّف القناة فقط ورقم القسم (topic) يُهمَل.

**بعد r66:**
- الرابط الذي يحمل رقم قسم (`t.me/القناة/رقم_القسم`) يُستخرج منه رقم القسم
  (`extractThreadId`) ويُضاف **قسماً منفصلاً** تحت القناة الموجودة:
  - الجدول موجود (محلياً دوماً، وفي الإنتاج إن نُفِّذ `supabase_telegram_topics.sql`):
    صف في `telegram_topics` (سنة/مقياس/عام) — منشوراته تُصنَّف حتمياً إلى نطاقه (r65).
  - **الجدول غائب (حالة الإنتاج الحالية): المسار البديل الجديد r66** — القسم يُخزَّن
    **مصدراً مستقلاً** بمعرّف مركّب `chatId:threadId` في `telegram_sources` نفسها
    (العمود TEXT فريد — لا يحتاج أي DDL)، يرث أعمدة قناته الأم (تخصص/نوع/ملمح)
    ويحمل ربط السنة/المقياس عليه مباشرة، ويظهر في قائمة المصادر صفاً مستقلاً
    باسم «القناة • القسم».
- الاستيراد (`ingest`): منشور داخل موضوع يُبحث أولاً بمُعرّفه المركّب — فإن وُجد قسم
  مربوط حكم ربطه حتمياً (المصدر المربوط يفوز دائماً كبقية قرارات المشرف)، وإلا يرجع
  لمستوى القناة كما كان. روابط t.me تُبنى سليمة مع القسم (تُجرَّد لاحقة `:thread`
  من المعرّف المركّب عند بناء الرابط).
- إعادة لصق نفس القسم → **تحديث** الربط لا تكرار (UNIQUE)، والقناة الكاملة بلا رقم
  تبقى 409 مع توجيه واضح للصق رابط القسم.
- الحمايات نفسها: رابط قسم بلا سنة/مقياس → 400 بتوجيه؛ سنة لا تتبع التخصص → 403؛
  قناة تخصص آخر → 403 (المالك فقط ينقل)؛ الطالب → 403.
- الواجهة: حقل الرابط يقبل روابط الأقسام، تلميح حيّ يتغير عند لصق رابط قسم، حقل
  «اسم القسم»، ورسائل نجاح تصف ما سيحدث («منشوراته القادمة ستُصنَّف تلقائياً إلى
  نطاقه ولا تظهر لغيره»)، وكل قناة تعرض «• N أقسام مرتبطة».

## ٢) العزل التلقائي للسنوات (داخلي بلا اختيار الطالب)

**قبل r66:** القفل كان يعتمد على `scopeAcademicYearId` في ملف الطالب فقط — الطالب
المنضم عبر فوج (join request) لا يملكه فلا يُقفل له شيء.

**بعد r66 (`resolveMyYearId`):** سنة الطالب/الممثل تُشتق **داخل الخادم**:
نطاقه إن وُجد، وإلا **سنة فوجه المنضم إليه** (آخر طلب انضمام مقبول). المكتبة تقفل
عليها دائماً للطلبة/الممثلين (مع تجاهل أي `yearId` مزيّف)، والاستجابة تتضمن
`yearLock: {yearId, yearName}` تعرضه الواجهة كبطاقة «تعرض مكتبة سنتك فقط تلقائياً»،
وخيارات المقاييس تُفلتر على السنة المقفلة، بينما المشرف/المالك يتصفحان أي سنة.

## ٣) «اعتنِ بجدول Supabase» — أُنجزت بلا خطوة يدوية

- **المفاتيح المرسَلة (`sb_publishable_…` + JWT) تخص مشروعاً آخر غير موجود أصلاً في
  DNS (محذوف أو خاطئ) — ليست مفاتيح مشروع الإنتاج، ولا يمكن لأي مفتاح anon إنشاء
  جدول بتصميم Supabase (DDL = محرر SQL فقط).**
- لذلك اعتنينا بالأمر من داخل التطبيق نفسه: **المسار البديل أعلاه يجعل الأقسام تعمل
  في الإنتاج اليوم بلا تنفيذ أي SQL** — تحقق مباشر على قاعدة الإنتاج الحقيقية
  (`scripts/r66-prod-section-verify.mjs`): إدراج قسم مركّب تحت قناة ENS الحقيقية
  (id=6)، قراءته، رفض التكرار (UNIQUE)، حذفه الذاتي — **كل الخطوات نجحت** ولا أثر متبقٍ.
- تبقى خطوة **اختيارية** لمن يريد إدارة الأقسام من حوار «#» الكامل (عام/مقياس/سنة
  لكل موضوع): تنزيل `download/supabase_telegram_topics.sql` ولصقه في
  Supabase Dashboard → SQL Editor → Run. بدونها يعمل كل شيء كما وصفت أعلاه.
- ملاحظة أمنية قديمة (r20) ما تزال قائمة: مفتاح anon للإنتاج موجود في تاريخ git
  العام مع سياسات RLS تسمح بالكتابة على جداول تيليجرام — يُستحسن تدويره يوماً ما
  (لن يكسر التطبيق: تكوين Vercel مستقل).
