# تعليمات التنظيف

قبل أي حذف، نفّذ خطوة الأمان أولًا، ثم اعرض النتيجة عليّ، ثم انتظر موافقتي على الحذف الفعلي (حسب قاعدة "لا تنفّذ قبل الموافقة").

## خطوة الأمان أولًا (إلزامية قبل أي حذف)
لكل مجلد من القائمة أدناه، ابحث (Grep) في `src/` و`prisma/` عن أي `import` أو مسار (`require`, `readFile`, إلخ) يشير إليه. اعرض النتيجة: "لا يوجد استدعاء" أو "وُجد استدعاء في الملف كذا" لكل مجلد، قبل حذف أي شيء.

## المجلدات المرشّحة للحذف (بعد تأكيد خطوة الأمان)
- `skills/` — مجلد أدوات عامة من منصة z.ai، غير مرتبط بمشروع "طالب"
- `examples/` — مثال تجريبي عام (websocket) لا علاقة له بالمشروع
- `tests/` — سكربتات Shell عامة (`python-runtime-*`, `database-runtime-*`) لا تخص منطق التطبيق
- `tool-results/` — سجلات تنفيذ أوامر داخلية قديمة (نصوص bash/read)، ليست كودًا
- `mini-services/` — افحص محتواه أولًا واذكر ماذا يحتوي بالضبط قبل الحذف (لم يُفحص بعد)
- محتوى `download/` القديم (لقطات شاشة `.png` من مراحل تجربة سابقة، وملفات `.sql` مكرَّرة إن وُجدت) — اعرض القائمة الكاملة أولًا قبل الحذف

## فحص إضافي إلزامي: ملفات محلية غير مرفوعة على GitHub أصلًا
لا تكتفِ بتنظيف ما هو مرفوع على GitHub فقط — افحص أيضًا بيئة العمل المحلية الحالية (الحاوية/المجلد الذي تشتغل فيه فعليًا) وأخبرني بما يلي تحديدًا:
- هل يوجد ملف قاعدة بيانات محلي (`.db`, `dev.db`, أو أي ملف SQLite) متبقٍّ من مسار Prisma المحلي القديم؟ اذكر حجمه ومساره.
- هل يوجد مجلدا `node_modules/` أو `.next/` (مجلدات بناء تلقائية، آمن حذفها دائمًا وتُعاد تلقائيًا عند التشغيل التالي)؟ اذكر حجم كل واحد.
- هل توجد أي ملفات أو مجلدات أخرى **غير موجودة إطلاقًا في نسخة GitHub** (يعني أنشأتها الأداة محليًا ونسيت رفعها أو حذفها)؟ اعرض قائمة كاملة بها قبل أي حذف.
- شغّل أمرًا لحساب المساحة الكلية المستخدمة في مجلد المشروع بالكامل، واذكر أكبر 10 عناصر من حيث الحجم تحديدًا (بغض النظر هل هي على GitHub أم لا).

اعرض كل هذا كتقرير واحد شامل قبل حذف أي شيء، وانتظر موافقتي.

## لا تحذف هذه تحت أي ظرف
`prisma/`, `src/`, `public/`, `scripts/` (يحتوي `seed.ts` و`update-supabase-schema.ts` المفيدين)، وكل ملفات الإعداد في الجذر (`package.json`, `tsconfig.json`, `next.config.ts`, `tailwind.config.ts`, `vercel.json`, `components.json`, `.env`, `.gitignore`)

بعد التنظيف، أخبرني بحجم المساحة الذي تحرَّر تقريبًا وعدد الملفات المحذوفة.

# قاعدة جديدة تُضاف لقواعد العمل — منع فقدان الملفات أثناء Git

## السياق
حدث سابقًا فقدان 3 ملفات شاشات كاملة (`assignments-screen.tsx`, `group-screen.tsx`, `browse-groups-screen.tsx`) بسبب `git pull --rebase` حُلَّت تعارضاته بطريقة أدّت لحذف ملفات غير متعارضة أصلًا بصمت. هذه القاعدة تمنع تكرار هذا.

## القاعدة
10. **قبل أي عملية `git rebase` أو `git merge` أو حل تعارضات (Conflicts):**
    - سجّل عدد وأسماء كل الملفات الموجودة حاليًا في `src/components/talib/screens/` (أو أي مجلد شاشات رئيسي) **قبل** العملية.
    - بعد انتهاء العملية، قارن القائمة نفسها **بعد**ها مباشرة.
    - لو اختفى أي ملف كان موجودًا قبل العملية ولم يُذكر صراحة أنه حُذف عمدًا بطلب مني، **توقف فورًا وأخبرني قبل أي Push** — لا تكمل العمل والملف مفقود.
11. **لا تستخدم `git checkout --theirs` أو `--ours` بشكل تلقائي دون توضيح لي أي جانب يمثل كل خيار في هذه العملية تحديدًا** (المعنى يختلف بين `merge` و`rebase`، وهذا كان سبب الالتباس الذي أدى لفقدان الملفات).
12. **بعد أي عملية Git معقّدة (rebase/merge/force-push)، اعرض ملخصًا: كم ملفًا تغيّر، كم أُضيف، كم حُذف** — قبل أن تعتبر العملية ناجحة أو تنتقل لأي شيء آخر.
